title: "Server Statistics"
description: "HTTP API endpoints for monitoring SRS server health, resource usage, virtual hosts, and performance."
keywords: ["server stats", "monitoring", "cpu", "memory", "vhosts", "srs api"]
---

The server statistics endpoints expose real-time information about the SRS process, host system resources, virtual hosts, and enabled features. All endpoints are read-only `GET` requests.

<Note>
  The HTTP API must be enabled. See the [HTTP API Overview](/api/overview) for configuration details.
</Note>

## Endpoint reference

| Method | Path                          | Description                              |
|--------|-------------------------------|------------------------------------------|
| GET    | `/api/v1/versions`            | Server version numbers                   |
| GET    | `/api/v1/summaries`           | Overall server summary (CPU, mem, conns) |
| GET    | `/api/v1/rusages`             | POSIX resource usage (`getrusage`)       |
| GET    | `/api/v1/self_proc_stats`     | Linux `/proc/self/stat` fields           |
| GET    | `/api/v1/system_proc_stats`   | System-wide CPU stats                    |
| GET    | `/api/v1/meminfos`            | System memory statistics                 |
| GET    | `/api/v1/authors`             | License and contributor list             |
| GET    | `/api/v1/features`            | Compiled feature flags                   |
| GET    | `/api/v1/requests`            | Echo the incoming HTTP request           |
| GET    | `/api/v1/vhosts`              | List all virtual hosts                   |
| GET    | `/api/v1/perf`                | Performance counters                     |

## GET /api/v1/versions

Returns the SRS version as major, minor, and revision integers.

<CodeGroup>

```bash curl
curl http://localhost:1985/api/v1/versions
```

</CodeGroup>

```json
{
  "code": 0,
  "server": "vid-k23d8x3",
  "service": "svc-a1b2c3d",
  "pid": "12345",
  "data": {
    "major": 5,
    "minor": 0,
    "revision": 201,
    "version": "5.0.201"
  }
}
```

<ResponseField name="data.major" type="integer">
  Major version number.
</ResponseField>

<ResponseField name="data.minor" type="integer">
  Minor version number.
</ResponseField>

<ResponseField name="data.revision" type="integer">
  Revision / patch number.
</ResponseField>

<ResponseField name="data.version" type="string">
  Full dotted version string (e.g. `"5.0.201"`).
</ResponseField>

    <ResponseField name="srs_recv_bytes" type="integer">Total bytes received by SRS since last sample.</ResponseField>
    <ResponseField name="srs_send_bytes" type="integer">Total bytes sent by SRS since last sample.</ResponseField>
  </Expandable>
</ResponseField>

## GET /api/v1/rusages

<CodeGroup>

```bash curl
curl http://localhost:1985/api/v1/rusages
```

</CodeGroup>

```json
{
  "code": 0,
  "server": "vid-k23d8x3",
  "service": "svc-a1b2c3d",
  "pid": "12345",
  "data": {
    "ok": true,
    "sample_time": 1712345678,
    "ru_utime": 142,
    "ru_stime": 18,
    "ru_maxrss": 24576,
    "ru_ixrss": 0,
    "ru_idrss": 0,
    "ru_isrss": 0,
    "ru_minflt": 31200,
    "ru_majflt": 0,
    "ru_nswap": 0,
    "ru_inblock": 0,
    "ru_oublock": 456,
    "ru_msgsnd": 0,
    "ru_msgrcv": 0,
    "ru_nsignals": 0,
    "ru_nvcsw": 120430,
    "ru_nivcsw": 843
  }
}
```

<ResponseField name="data.ru_utime" type="integer">User CPU time used, in seconds.</ResponseField>
<ResponseField name="data.ru_stime" type="integer">System CPU time used, in seconds.</ResponseField>
<ResponseField name="data.ru_maxrss" type="integer">Maximum resident set size in kilobytes.</ResponseField>
<ResponseField name="data.ru_minflt" type="integer">Minor page faults (no I/O required).</ResponseField>
<ResponseField name="data.ru_majflt" type="integer">Major page faults (required disk I/O).</ResponseField>
<ResponseField name="data.ru_nvcsw" type="integer">Voluntary context switches.</ResponseField>
<ResponseField name="data.ru_nivcsw" type="integer">Involuntary context switches.</ResponseField>

## GET /api/v1/self_proc_stats

Returns detailed fields from Linux `/proc/self/stat` for the SRS process. Most fields correspond directly to the `/proc/[pid]/stat` format.

<CodeGroup>

```bash curl
curl http://localhost:1985/api/v1/self_proc_stats
```

</CodeGroup>

```json
{
  "code": 0,
  "server": "vid-k23d8x3",
  "service": "svc-a1b2c3d",
  "pid": "12345",
  "data": {
    "ok": true,
    "sample_time": 1712345678,
    "percent": 1.45,
    "pid": 12345,
    "comm": "srs",
    "state": "S",
    "ppid": 1,
    "pgrp": 12345,
    "session": 12345,
    "utime": 28400,
    "stime": 3600,
    "num_threads": 4,
    "vsize": 524288000,
    "rss": 24576
  }
}
```

<ResponseField name="data.percent" type="number">CPU usage percentage for this process.</ResponseField>
<ResponseField name="data.state" type="string">Process state character (e.g. `"S"` for sleeping, `"R"` for running).</ResponseField>
<ResponseField name="data.utime" type="integer">Time spent in user mode, in clock ticks.</ResponseField>
<ResponseField name="data.stime" type="integer">Time spent in kernel mode, in clock ticks.</ResponseField>
<ResponseField name="data.num_threads" type="integer">Number of threads in the process.</ResponseField>
<ResponseField name="data.vsize" type="integer">Virtual memory size in bytes.</ResponseField>
<ResponseField name="data.rss" type="integer">Resident set size in pages.</ResponseField>

## GET /api/v1/requests

Echoes the incoming HTTP request back in the response body. Useful for debugging proxies, headers, and request routing.

<CodeGroup>

```bash curl
curl http://localhost:1985/api/v1/requests
```

</CodeGroup>

```json

  "code": 0,

  "pid": "12345",

    "uri": "http://localhost:1985/api/v1/requests",

    "METHOD": "GET",
    "headers": {
      "Host": "localhost:1985",
      "User-Agent": "curl/8.4.0",
      "Accept": "*/*"
    }
  }

```

## GET /api/v1/vhosts

Returns a list of all configured virtual hosts with their stream and client counts and bandwidth usage.

<CodeGroup>

```bash list all vhosts
curl http://localhost:1985/api/v1/vhosts
```

```bash get single vhost
curl http://localhost:1985/api/v1/vhosts/<vhost_id>
```

</CodeGroup>

```json
{
  "code": 0,
  "server": "vid-k23d8x3",
  "service": "svc-a1b2c3d",
  "pid": "12345",
  "vhosts": [
    {
      "id": "vid-001",
      "name": "__defaultVhost__",
      "enabled": true,
      "clients": 12,
      "streams": 3,
      "send_bytes": 10485760,
      "recv_bytes": 204800,
      "kbps": {
        "recv_30s": 800,
        "send_30s": 4200
      }
    }
  ]
}
```

<ResponseField name="vhosts[].id" type="string">Unique vhost identifier.</ResponseField>
<ResponseField name="vhosts[].name" type="string">Vhost domain name as configured.</ResponseField>
<ResponseField name="vhosts[].clients" type="integer">Number of connected clients on this vhost.</ResponseField>
<ResponseField name="vhosts[].streams" type="integer">Number of active streams on this vhost.</ResponseField>
<ResponseField name="vhosts[].send_bytes" type="integer">Total bytes sent for this vhost.</ResponseField>
<ResponseField name="vhosts[].recv_bytes" type="integer">Total bytes received for this vhost.</ResponseField>
<ResponseField name="vhosts[].kbps.recv_30s" type="integer">Inbound bitrate over the last 30 seconds, in kbps.</ResponseField>
<ResponseField name="vhosts[].kbps.send_30s" type="integer">Outbound bitrate over the last 30 seconds, in kbps.</ResponseField>

## GET /api/v1/perf

Returns internal performance counters such as coroutine scheduling statistics.

<CodeGroup>

```bash curl
curl http://localhost:1985/api/v1/perf
```

</CodeGroup>

```json
{
  "code": 0,
  "server": "vid-k23d8x3",
  "service": "svc-a1b2c3d",
  "pid": "12345",
  "data": {
    "ok": true,
    "sample_time": 1712345678,
    "sched": {
      "nn_loop": 1024000,
      "nn_timer": 204800,
      "nn_msgs": 8192000
    }
  }
}
```

<ResponseField name="data.sched.nn_loop" type="integer">Total coroutine event loop iterations since start.</ResponseField>
<ResponseField name="data.sched.nn_timer" type="integer">Total timer events fired since start.</ResponseField>
<ResponseField name="data.sched.nn_msgs" type="integer">Total messages processed since start.</ResponseField>
