SRS implements WebRTC signaling via four HTTP endpoints:

| Endpoint | Protocol | Description |
|----------|----------|-------------|
| `POST /rtc/v1/publish/` | WHIP (JSON) | Publish a stream using SRS JSON body format |
| `POST /rtc/v1/play/` | WHEP (JSON) | Play a stream using SRS JSON body format |
| `POST /rtc/v1/whip/` | WHIP (standard) | Publish using standard WHIP spec (SDP body, `Content-Type: application/sdp`) |
| `POST /rtc/v1/whip-play/` | WHEP (standard) | Play using standard WHEP spec (SDP body, `Content-Type: application/sdp`) |

The `/rtc/v1/publish/` and `/rtc/v1/play/` endpoints accept JSON bodies with an `sdp` field. The `/rtc/v1/whip/` and `/rtc/v1/whip-play/` endpoints accept raw SDP bodies per the WHIP/WHEP specifications.

Both endpoint pairs handle ICE candidate exchange and DTLS setup internally.

<Note>
  WebRTC requires the HTTP API to be enabled. See the [HTTP API Overview](/api/overview) for configuration.
</Note>

## Prerequisites

### Enable WebRTC

Add the following to your SRS configuration to accept WebRTC publishers and players:

```nginx srs.conf
rtc_server {
    enabled     on;
    listen      8000;        # UDP port for media
    candidate   <your_server_ip>;
}

vhost __defaultVhost__ {
    rtc {
        enabled     on;
        rtmp_to_rtc off;
        rtc_to_rtmp off;
    }
}
```

### Set CANDIDATE for production

<Warning>
  You must set `candidate` to your server's public IP address. If it is set to `127.0.0.1` or left as `auto`, remote clients cannot establish a media connection.
</Warning>

```nginx srs.conf
rtc_server {
    enabled     on;
    listen      8000;
    # Set this to the server's public IP or hostname
    candidate   203.0.113.10;
}
```

Alternatively, set the `SRS_RTC_SERVER_CANDIDATE` environment variable before starting SRS.

### RTMP ↔ WebRTC conversion

To publish via RTMP and play via WebRTC (or vice versa), enable the conversion options in your vhost:

```nginx srs.conf
vhost __defaultVhost__ {
    rtc {
        enabled         on;
        rtmp_to_rtc     on;   # convert RTMP publish to WebRTC playback
        rtc_to_rtmp     on;   # convert WebRTC publish to RTMP playback
    }
}
```

### HTTPS requirement for browsers

<Warning>
  Browsers enforce secure contexts for WebRTC. If SRS is not behind a TLS-terminating proxy, you must enable the HTTPS API:

  ```nginx
  http_api {
      enabled on;
      listen  1985;
      https {
          enabled on;
          listen  1990;
          key     ./conf/server.key;
          cert    ./conf/server.crt;
      }
  }
  ```

  For production deployments, use a reverse proxy (Nginx, Caddy) to terminate TLS and forward to SRS.
</Warning>

## POST /rtc/v1/publish/

Initiates a WebRTC publish session (WHIP). Send an SDP offer from the browser or encoder; SRS returns an SDP answer. After a successful exchange the client begins sending media over UDP.

### Request body

```json
{
  "api": "http://192.168.1.10:1985/rtc/v1/publish/",
  "clientip": "203.0.113.45",
  "sdp": "v=0\r\no=- 46117317 2 IN IP4 127.0.0.1\r\n...",
  "streamurl": "rtmp://192.168.1.10/live/livestream",
  "tid": "tid-a1b2c3d4"
}
```

<ParamField body="api" type="string" required>
  The full URL of this API endpoint. SRS uses this to construct the ICE candidate URLs included in the SDP answer.
</ParamField>

<ParamField body="sdp" type="string" required>
  The SDP offer from the WebRTC publisher. Must be a valid SDP string as generated by `RTCPeerConnection.createOffer()` or an equivalent encoder.
</ParamField>

<ParamField body="streamurl" type="string" required>
  RTMP-style stream URL identifying the target vhost, application, and stream name. Format: `rtmp://<host>/<app>/<stream>`.
</ParamField>

<ParamField body="clientip" type="string">
  The real client IP address. Useful when SRS is behind a proxy and the actual remote IP is in a custom header. If omitted, SRS uses the connection's remote IP.
</ParamField>

<ParamField body="tid" type="string">
  Caller-supplied transaction ID for correlating requests and log entries. Arbitrary string.
</ParamField>

### Response

```json
{
  "code": 0,
  "server": "vid-k23d8x3",
  "sdp": "v=0\r\no=SRS/5.0.201 1 2 IN IP4 203.0.113.10\r\n...",
  "sessionid": "d4e5f6a7-b8c9-0d1e-2f3a-4b5c6d7e8f90"
}
```

<ResponseField name="code" type="integer">
  `0` on success. Non-zero values indicate an error; check the SRS log for details.
</ResponseField>

<ResponseField name="server" type="string">
  The unique server ID.
</ResponseField>

<ResponseField name="sdp" type="string">
  The SDP answer from SRS. Pass this to `RTCPeerConnection.setRemoteDescription()` in the browser to complete the offer/answer exchange.
</ResponseField>

<ResponseField name="sessionid" type="string">
  Unique identifier for this WebRTC session. Used to correlate log entries and for future session management.
</ResponseField>

### Full curl example

```bash
curl -X POST http://localhost:1985/rtc/v1/publish/ \
  -H "Content-Type: application/json" \
  -d '{
    "api":       "http://localhost:1985/rtc/v1/publish/",
    "clientip":  null,
    "sdp":       "v=0\r\no=- 4611731 2 IN IP4 127.0.0.1\r\ns=SRS/5.0.201\r\nt=0 0\r\na=group:BUNDLE 0 1\r\nm=audio 9 UDP/TLS/RTP/SAVPF 111\r\nc=IN IP4 0.0.0.0\r\na=sendonly\r\nm=video 9 UDP/TLS/RTP/SAVPF 102\r\nc=IN IP4 0.0.0.0\r\na=sendonly\r\n",
    "streamurl": "rtmp://localhost/live/livestream",
    "tid":       "tid-a1b2c3d4"
  }'
```

## POST /rtc/v1/play/

Initiates a WebRTC play session (WHEP). Send an SDP offer from the browser; SRS returns an SDP answer. After a successful exchange the client receives media over UDP.

### Request body

```json
{
  "api": "http://192.168.1.10:1985/rtc/v1/play/",
  "clientip": "203.0.113.45",
  "sdp": "v=0\r\no=- 46117317 2 IN IP4 127.0.0.1\r\n...",
  "streamurl": "rtmp://192.168.1.10/live/livestream",
  "tid": "tid-b2c3d4e5"
}
```

<ParamField body="api" type="string" required>
  The full URL of this API endpoint. Used to build ICE candidates in the SDP answer.
</ParamField>

<ParamField body="sdp" type="string" required>
  The SDP offer from the WebRTC player. Must be generated by `RTCPeerConnection.createOffer()` with `recvonly` direction.
</ParamField>

<ParamField body="streamurl" type="string" required>
  RTMP-style stream URL identifying the stream to play. Format: `rtmp://<host>/<app>/<stream>`.
</ParamField>

<ParamField body="clientip" type="string">
  Real client IP when SRS is behind a proxy.
</ParamField>

<ParamField body="tid" type="string">
  Caller-supplied transaction ID.
</ParamField>

### Response

```json
{
  "code": 0,
  "server": "vid-k23d8x3",
  "sdp": "v=0\r\no=SRS/5.0.201 1 2 IN IP4 203.0.113.10\r\n...",
  "sessionid": "e5f6a7b8-c9d0-1e2f-3a4b-5c6d7e8f90a1"
}
```

<ResponseField name="code" type="integer">
  `0` on success.
</ResponseField>

<ResponseField name="sdp" type="string">
  The SDP answer. Pass this to `RTCPeerConnection.setRemoteDescription()` in the browser.
</ResponseField>

<ResponseField name="sessionid" type="string">
  Unique identifier for this play session.
</ResponseField>

### Full curl example

```bash
curl -X POST http://localhost:1985/rtc/v1/play/ \
  -H "Content-Type: application/json" \
  -d '{
    "api":       "http://localhost:1985/rtc/v1/play/",
    "clientip":  null,
    "sdp":       "v=0\r\no=- 4611731 2 IN IP4 127.0.0.1\r\ns=SRS/5.0.201\r\nt=0 0\r\na=group:BUNDLE 0 1\r\nm=audio 9 UDP/TLS/RTP/SAVPF 111\r\nc=IN IP4 0.0.0.0\r\na=recvonly\r\nm=video 9 UDP/TLS/RTP/SAVPF 102\r\nc=IN IP4 0.0.0.0\r\na=recvonly\r\n",
    "streamurl": "rtmp://localhost/live/livestream",
    "tid":       "tid-b2c3d4e5"
  }'
```

## WebRTC session flow

The complete publish flow is:

1. Browser calls `getUserMedia()` to capture audio/video.
2. Browser creates an `RTCPeerConnection` and calls `createOffer()`.
3. Browser `POST`s the SDP offer to `/rtc/v1/publish/` with the stream URL.
4. SRS returns an SDP answer.
5. Browser calls `setRemoteDescription(answer)` to complete the exchange.
6. ICE and DTLS complete; media flows over UDP on port `8000`.

The play flow is identical but in reverse: SRS sends media to the browser.

---

## WHIP standard compliance

The `/rtc/v1/publish/` endpoint follows the [WHIP draft specification](https://datatracker.ietf.org/doc/draft-ietf-wish-whip/). WHIP-compatible encoders (e.g. OBS 30+, GStreamer with `whipsink`) can publish to SRS using a URL in this form:

```
http://<server>:1985/rtc/v1/whip/?app=live&stream=livestream
```

<Tip>
  OBS Studio 30+ supports WHIP natively. Set the service to "WHIP" and enter the URL above as the server.
</Tip>
